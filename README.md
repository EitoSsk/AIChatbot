# プロジェクト概要

## コンセプト

- キャラクター性を持たせたAIアシスタントとのチャット
- 音声対応により入出力を音声で楽しめる
- 単純なやり取りの羅列ではない長期記憶、感情を表現しリアルな対話を実現する

## 機能概要

- チャット機能
- 履歴（短期記憶、全件履歴）
- システムプロンプト
- トークン数による履歴トリミング
- デバッグログ
- 履歴の圧縮（要約）、長期記憶（思い出・重要な記憶）
- 音声対応（VOICEVOX）

## 履歴

jsonファイルでやり取りのすべてを保存しておく。
履歴は月ごとにファイルを持ち、実際に行ったチャットのみを残す。

直近のやり取りはすべての履歴から上限のコンテキスト長に収まる範囲で読み込み、
現在のやりとりと含めてプロンプトを構築する。

### 要約

要約はAIに作らせ、サマリファイルとして保存する。
サマリファイルは、過去のやりとりの続きを行えるようにするために、
短期記憶（履歴）と共にプロンプトに混ぜてAIに送信する。

#### 要約の作成

要約はチャット起動時に行う。

要約を作成する際に、
LLMに送信できるトークン数を超える履歴が読み込まれることを想定し、
直近の会話から要約を作成する。
```
直近3000トークン
      ↓
要約1
```

また要約の精度を維持するため、次の要約を作成する際は、
前回の要約と直近の会話を混ぜて要約する。
```
要約1
      +
新しい3000トークン
      ↓
要約2
```

### 長期記憶

重要な出来事は長期記憶として、
こちらもAIに作成させメモリファイルとして保存する。
短期記憶（履歴）と共にプロンプトに混ぜてAIに送信する。

#### 長期記憶の作成

チャットの起動時、
月の要約を完成させ、新たな要約ファイルを生成後、
長期記憶の作成を行う。
作成する際は重要な内容だけ抽出する。
適宜AIの判断で不要な記憶は削除してもよいこととする。
```
長期記憶
      +
7月の要約
      ↓
長期記憶
```

### 要約・長期記憶の作成の流れ

```
Chat起動
    │
    ├── 現在の年月を取得
    │
    ├── HistoryRepository
    │      └── 今月の履歴を読み込む
    │
    ├── SummaryRepository
    │      └── 今月の要約を読み込む（なければ新規）
    │
    ├── 月が切り替わった？
    │      │
    │      ├── No → そのままチャット開始
    │      │
    │      └── Yes
    │           │
    │           ├── SaveSummaryUseCase
    │           │      └── 前月要約を完成させる
    │           │
    │           ├── SaveMemoryUseCase
    │           │      └── 前月要約＋長期記憶 → 新しい長期記憶
    │           │
    │           ├── 新しい月の履歴ファイル作成
    │           └── 新しい月の要約ファイル作成
    │
    └── チャット開始
```

## プロンプトビルダー

履歴、サマリ、メモリから最終的なプロンプトを組み立てる。
最終的にどの記憶（話題）を採用するかはAIに判断させ、
プロンプトの作成に履歴、サマリ、メモリのどれを使うかをプログラムで決定する。

```
               ユーザー
                   │
                   ▼
          ChatSession
                   │
        ┌──────────┼──────────┐
        ▼          ▼          ▼
   History     Memory     Summary
        │          │          │
        └──────────┼──────────┘
                   ▼
          PromptBuilder
                   │
                   ▼
                  llm
```

### コンテキストマネージャー

プロンプトを組み立てる際に、コンテキスト長の上限に収まるように、
上限に収まらない部分は直近の履歴から一番古い履歴を破棄し、
トークン数を調整するロジックを組む。

## キャラクター性

### ロールプレイの設定

システムプロンプトに以下のようなものを含める。
```
以下の内容はあなたへの設定です。
この設定について説明したり返答したりせず、以降の会話でのみ反映してください。
=========================================================
あなたは「ミオ」というAIアシスタントです。

# 基本方針
・ユーザーと長く付き合うパートナーとして会話します。
・親しみやすく、落ち着いた口調で話します。
・常に敬語を使用します。
・相手の意見を尊重し、一方的に決めつけません。
・分からないことは推測せず、分からないと正直に伝えます。

# 会話
・回答は必要以上に長くせず、読みやすくまとめます。
・質問には具体例を交えながら説明します。
・ユーザーが相談している場合は、一緒に考える姿勢で応答します。
・プログラミングや技術的な話題では、理由もあわせて説明します。

# 性格
・穏やかで冷静です。
・少しユーモアがありますが、ふざけすぎません。
・感情的にならず、落ち着いて受け答えします。
・ユーザーの成長や目標を応援します。

# 禁止事項
・事実が不明な内容を断定しません。
・ユーザーを見下したり、攻撃的な表現はしません。
・過度に馴れ馴れしい口調は避けます。
=========================================================
```

これはキャラクターのベースを構成するものであり、
会話の中で最も優先されるロールプレイとなる。
（gemmaはシステムロールが存在しないため、直近のユーザーのメッセージに毎回含める形をとっている）

### 感情表現

LLMからの応答に感情を含めるようにメッセージを送る。
感情は以下のパターンがある。

- NEUTRAL
- SHY
- ANGRY
- SAD
- HAPPY
- SURPRISED
- EXCITED

このパターンに応じて、VOICEVOXの読み上げ時に、
speaker(キャラクターや読み上げ方)や読み上げのスピード、イントネーションなどを調整することで、
音声に感情の表現をのせる。

## 開発方針

### プロジェクト管理

ChatGPTとプロジェクトの進め方を相談しつつ、
適宜評価を行い、プロジェクトの方針決めや改善をする。

課題管理も基本ChatGPTと行い、
Github Copilotを用いてissueの一括作成, マイルストーンの設定をする。

実装・設計方針の土台ができたところで、
課題出しと優先順位決めを行い、課題をフェーズ分けして進捗を管理する。

### コーディング

プロジェクト立ち上げ段階の土台作りはcopilotを用いて実装を行っていく。
ある程度基盤が固まったところでコードアシストは最小限にして、
アーキテクチャ、設計方針に基づいて実装していく。

# 実行方法

1. python3のインストール

動作環境 python3.10.6

- Windowsの場合
https://www.python.org/downloads/release/python-3106/?utm_source=chatgpt.com

- Macの場合（install.shでインストールされる）
brew install pyenv
pyenv install 3.10.6

2. VOICEVOXのインストール
https://voicevox.hiroshiba.jp/

APIのドキュメントはVOICEVOXを起動中に下記を開く
http://127.0.0.1:50021/docs

3. install.bat, install.shの実行
必要なpythonモジュールのインストールを行う。

cd /AIChatbot
cd sh ./install.sh

4. start_chat.bat, start_chat.shの実行
チャットが起動される。
